# Artifacts: OpenUI out, documents back

18 September 2026. The decision, what it reverses, and what it cost.

---

## The decision

**OpenUI is removed from this product entirely.** A report, a plan, a guide, a
deck or a spreadsheet is a **file** again — `.docx`, `.pptx`, `.xlsx`, `.pdf` —
written with the matching skill and linked in the thread as a file card the
person can open, keep, print and send on.

The founder, 18 September:

> "all i said is that open ui to be the main thing for artifacts. not on .xlsx
> cause open ui dont have that. what i said is for reports/plans/guided doc and
> all ppt to be generated by open ui, cause i like their design. then doc to
> come when its a very simple word doc. here's what we gonna do. remove open ui
> completely. we gonna start over with smarter choices. turn on the way artifact
> was. docx, .xlsx or .pptx."

## What went wrong, precisely

OpenUI was asked for as the **look** of an artifact. It became the artifact
itself, and then it became the way every shaped answer was drawn — which is how
the file the person could actually send on stopped being made at all.

Two rules did the damage, and both were written by an agent rather than asked
for:

1. `MANAGED_DELIVERABLE_LINKS_PROMPT` was rewritten to say *"never make a
   `.docx`, `.xlsx` or `.pptx` unless the person asked for that file in those
   words."*
2. The `docx`, `xlsx`, `pptx` and `pdf` skills were set `enabled: false` in
   `desktop/SKILLs/skills.config.json`.

Together those made a Word document unreachable: the brief forbade it and the
skill that writes it was switched off.

**The tell was sitting in the harness the whole time.** `harness/main.tsx` had a
screen called "proactive", built from the founder's own words of 18 September:

> "i want for caisra take over in text and say i've put this as a word doc as
> well for you and that will be the artifact… thats how we win users. always
> proactive. the whole goal of the agent is that it does stuff for you. you
> shouldnt have to ask him he should take initiative like this."

The screen built to demonstrate that drew an OpenUI `ReportView` in a bubble.
The founder asked for a Word doc, said the words "word doc", and the screen
proving the feature shipped without one.

## What changed

| | Before | Now |
|---|---|---|
| A report, plan, guide | an in-thread rendered block | a `.docx` file, linked |
| A deck | an in-thread `SlideShow` | a `.pptx` file, linked |
| A spreadsheet | "not an artifact" | an `.xlsx` file, linked |
| `docx`/`xlsx`/`pptx`/`pdf` skills | `enabled: false` | `enabled: true` |
| Offering one unasked | allowed, as a card | expected, as a file |
| The `card` thread kind | drew a program in a bubble | removed |

**Removed from the tree:** `shared/cards/`, `shared/artifacts/`,
`thread/CardBlock.tsx`, `thread/ArtifactBlock.tsx`, the three stylesheets, both
prompt builders, the two generator scripts, the harness card examples, the five
`@openuidev/*` dependencies, and `InterVariable.woff2`, which nothing loaded
once the artifact stylesheet went.

The thread now has **nine** message kinds. Nothing renders a program in a bubble.

## Why not keep it for decks

It was considered, because the founder liked the design and said so more than
once. It was not kept for one reason: a deck that lives in a conversation cannot
be emailed, printed, opened in Keynote or handed to a colleague, and every one
of those is what somebody wants a deck *for*. The same argument that made a
`.docx` the right answer for a report makes a `.pptx` the right answer for a
deck. Two artifact systems, one of which cannot leave the app, is the thing that
caused this.

## The lesson that survives

The first rewrite of the deliverables section found something true and drew the
wrong conclusion from it: two sections of the brief were deciding the same
question, 26,000 characters apart, and the later one won. That is real and it is
now guarded by `briefConsistency.test.ts`. What was wrong was deciding the
question in favour of the thing the founder had not asked for.

**One section decides where a shaped answer lives: `## Documents You Make`.**

## Not done in this change

- **Images still have no server route.** `caisra_image_generate` is unblocked
  in the app and the agent is now told it exists, but the endpoint it calls,
  `/api/media/images/models` on the Claidor server, returns **404** — measured
  18 September. See `docs/product/images-state.md`.
