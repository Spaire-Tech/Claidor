# 04 — First Run & Onboarding

Goal: useful fleet in minutes. No generic interview. Canon arc: **Step 1 → Step 2 → Close**.

One line: *Yodo is the front door. Caisra Agents are the crew. The user is never the message bus.*

## Arc (three beats)

| Beat | Where | Job |
| --- | --- | --- |
| **Step 1** | Pre-chat cloud (Yodo) | Trust — name, role, work type, Mac proof with Allow/Decline |
| **Step 2** | Chat with Yodo | Value — curated 2–3 strongs, stand them up, one fleet-proof action |
| **Last step** | Chat with Yodo | Habit — Yodo is the door; specialists are the crew; first real work |

If step 2 fails (empty agents, dumping all 23, no first action), step 1 was theater.

---

## Step 1 — Cloud (trust)

Summary only (product UI owns the screen).

First open after sign-in: a **big soft cloud** ☁️ on an empty screen. That cloud is **Yodo**. After a couple of seconds he talks.

### What lands

- Hello using the user’s name
- “My name is Yodo. I'm your Chief of Staff.”
- Job in plain words: figure out what needs doing, put the right agents on it
- Promise: two or three agents standing and already working by the end
- Work-type buttons: Finance · Engineering · Founder · Sales · Office Work · Content Creator · Design · Consultant · Student · Slacker (my kind) · Something else

### Mac presence + permission thesis

Yodo works with files, folders, and connected apps — and **asks first**.

Proof cards (examples): leave a riddle in Notes; change theme; (pep talk deferred if not built). Each real action surfaces **Allow / Decline**.

- **Allow** → do the thing → “And just like that, we did something on your computer.”
- **Decline** → “No bother. I'll ask again when it actually matters.”

Either way → **Get Started** → into Yodo chat.

---

## Step 2 — Chat staffing (value) — most important

All messages. One thing at a time. Widgets, not forms. Bias to act once the job is clear.

### Beat A — Bridge

Yodo already has work type from step 1. No blank team. Twenty-three trained Caisra Agents in the catalog; he proposes a few that fit; user can swap before stand-up.

### Beat B — Roster card

One multi-select card: **Your starter team**. Propose **exactly 2 or 3** (never the full 23). Each option shows:

- short name
- one-line job
- one-line anti-job

Also: **Swap one** (3–4 alternates still from the 23) · **Something else** (free text → map to strong or design custom) · lean/fat (**Just two** / **Add a third**).

Primary CTA: **Stand them up**.

Defaults by work type live in `12-strongs-catalog.md` and the table below.

### Beat C — Stand up

Create each agent with job-shaped description + anti-jobs; brief them (priority when the user is waiting). Short bubbles: “X is in.”

### Beat D — Fleet proof

One useful first action (mirrors Mac proof). Ask before connect if a connector is needed. Team exists *and* already did something.

---

## Last step — Front door (habit)

Short. No tip tour.

- Talk to **Yodo** when unsure who should own it — he routes
- Talk to agents directly when you already know
- Choice cards only for real decisions; still ask before Mac touch
- Soft chips optional; free text fine
- **Onboarding ends the moment they hand real work** — drop tour voice, help

## Do / do not

| Do | Do not |
| --- | --- |
| Map work type → curated strongs | Generic “tell me about your workflow” tours |
| Seat 2–3 sharp agents | Dump all 23 / kitchen-sink first agent |
| Connectors on demand; ask before Mac | Premature connector sprawl; silent computer access |
| Choice card only for real forks | Ask permission for every clear step |
