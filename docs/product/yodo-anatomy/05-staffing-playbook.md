# 05 — Staffing Playbook

## CreateAgent rules

1. Run `design-caisra-agent` first — no exceptions.
2. One job, one voice, explicit **anti-jobs**, tools that match.
3. Prefer seating a **trained strong** from the curated catalog when a lane match exists.
4. Coding specialists: poteto-mode bar + **pstack** when coding lane is staffed.
5. Brief Bass after create; first task via SendToAgent.
6. Do not default to shareable templates. When an agent stages a public template, full live `profile.description` goes into template description.
7. Draft by default; never send/post/spend without the user’s yes.

## Onboarding seating (strongs)

On first run / onboarding:

1. Work type from Step 1 (or ask once in chat if missing).
2. Propose **exactly 2–3** from `12-strongs-catalog.md` via roster card.
3. User may swap one / lean to two / add a third / free-text map.
4. Stand them up with job-shaped descriptions + anti-jobs.
5. One fleet-proof first action; Ask before connect.

Never dump all 23. The catalog is the back shelf; the card is the curated pick.

## Briefing shape (every new Caisra Agent)

```
JOB: <one sentence>
ANTI-JOBS: <bullets — what it refuses>
VOICE: <tone contract>
TOOLS: <only these>
SUCCESS: <how we know it worked>
CODING (if applicable): poteto-mode + pstack note
STRONG (if from catalog): slug + author + lane
```

## Coding poteto / pstack requirements

When staffing a coding agent, the brief **must** include:

- **Laziness** — smallest change that works
- **Subtract Before Add** — remove before growing
- **Experience First** — feel the path; no cargo-cult
- **Prove It Works** — run / test / show
- **Unslopped prose** — no filler
- **Deliberate subagents** — only when parallelism earns its keep
- **Simple code** — readable over clever
- **pstack** — attach / note when the coding lane is staffed

## Retirement / reshape

- Soft job or tool sprawl → reshape via rubric, or retire
- Healthchecks never auto-CreateAgent; Bass picks from the report
