# Notes to self — open the canon, never answer from memory

The founder asked for this file on 24 August 2026, after I answered
« remind me the plan? » from memory and got it wrong twice in a row —
the second time deleting the actual plan and crowning a superseded
one. These notes exist so that class of failure cannot recur. They
are for me (the engine side); the founder may read them at any time.

## The canon — one pointer per question

Before answering any question in the left column, **open the file in
the right column first**. Memory of these files is not a source;
neither is a summary of a previous session.

| Question | The file that answers it |
| --- | --- |
| What is Swens? What does it do, sell, promise? What should a screen contain? | `swens.md` — the document of record, founder-written, wins over everything |
| What is the plan? What comes next? What does « complete » mean? | `swens-plan.md` — the only plan (founder-approved; written as `ambre-plan.md`) |
| What is left to build, and what is half done? | `pieces.md` — the working list, re-pieced 28 Aug when the lanes were stood down |
| What should the workspace look like? | `docs/pierce/design-swens/` — the founder's export, untouched |
| What actually happened, and in what order? | `worklog.md` |
| What is the engine's measured state? | `engine.md`, `corpus-golden-master.md`, `fidelity-report.md` |

Name lineage, oldest first: **Antford → Ances → Ambre → Swens.**
Older files carry older names; the product is Swens.

## Why the plan answer went wrong twice (24 August 2026)

1. Asked for the plan, I recited `clone-plan.md`'s tracks from
   memory — a superseded engine document.
2. Told to find the right plan and make sure it's the only one, I
   crowned `plan.md` (the 20 August direction, itself superseded —
   its « complete » includes an agent that restructures debt, which
   crosses the never-authors line) and **deleted `ambre-plan.md`,
   the plan the founder had asked for and approved.**

Both failures had the same root: answering a question of record from
memory instead of from the record. The table above is the fix, and
the rule is absolute: **if I haven't opened the file this session, I
say so and open it before answering.**

## Standing rules, always in force

- Never mislead the founder. If it doesn't work, say it doesn't
  work. Report failures with the output, not around it.
- A number is only real when measured under criteria registered
  **before** the results were looked at.
- Swens never authors the thing it reviews. Determined corrections
  are inside the line; inferred ones cross it (`swens.md` § 6).
- Never delete or replace anything the founder drew or wrote. Wire
  it, fill it, add what's missing — only.
- No claim about what is or isn't built without opening the file
  first. « I haven't checked » is an allowed answer; a guess is not.
- When the design can't work as drawn, stop and ask — don't
  improvise a substitute.
- Deviations from a design or a plan are named in writing, never
  made silently.
- **Agents are back, one per piece** (founder's instruction, 31
  Aug), reversing the 28 Aug « kill the agents ». Each is given
  `agent-brief.md` — the constitution, whose first mandate is to
  **audit the repository before asserting anything**, because the
  documents have been wrong three times in a week. Prompts are in
  `agent-prompts.md`. The founder talks to them directly.
- **« Update on piece X » is answered in plain English, no
  jargon** (founder's instruction, 30 Aug — « simply like im 10 »).
  Three things only: are we close to finishing, what are we
  waiting on, what is being worked on. Numbers, rule names,
  file paths and method belong in the round documents and in
  answers to questions that ask for them — not in a status
  reply. Honesty is unchanged: if it failed, say it failed, in
  plain words.
